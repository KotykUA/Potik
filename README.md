# Потік

Менеджер завантажень для Linux на Rust, GTK4 та libadwaita. Додайте пряме HTTP/HTTPS-посилання, виберіть папку й за потреби задайте назву файлу. Клавіші **Ctrl+N** відкривають форму додавання.

Якщо за посиланням сервер повертає вебсторінку, «Потік» показує попередження. Завантаження такої адреси доступне.

- До трьох одночасних завантажень. Для одного файлу можна задати від 1 до 32 потоків, до 16 на один сервер.
- Черга, пауза, відновлення та повтор після помилки. Вимкніть «Почати одразу», щоб додати завдання на паузі.
- Прогрес, швидкість і фільтри за станом завантаження. Для готового файлу можна відкрити сам файл або його папку.
- Черга й історія зберігаються між запусками. Під час закриття застосунок зберігає чергу й завершує свій процес aria2c. Під час наступного запуску активні завдання повертаються в чергу, а поставлені на паузу чекають на команду «Продовжити».

## Швидкість і параметри з’єднання

Для великих файлів aria2 паралельно запитує діапазони байтів і призначає вільним з’єднанням наступні доступні блоки. Якщо сервер підтримує постійні HTTP-з’єднання, aria2 може використати їх повторно. Фактична кількість з’єднань залежить від розміру файлу, підтримки HTTP Range та доступних джерел. Паралельні запити можуть прискорити завантаження, якщо сервер обмежує швидкість окремого з’єднання.

У формі додавання задайте ліміт швидкості для файлу в КіБ/с. Значення `0` означає «без обмежень». У «Параметрах з’єднання» можна додати дзеркала з ідентичним вмістом, по одному посиланню на рядок. Дзеркала на інших серверах дозволяють задіяти до 32 з’єднань загалом.

Там само можна задати User-Agent, URL сторінки завантаження (заголовок Referer), ім’я користувача й пароль для HTTP Basic. Ім’я та пароль діють для основного посилання. Після перезапуску натисніть «Повторити завантаження» й знову введіть дані для входу. Завантаження продовжиться зі збереженої точки, якщо сервер підтримує докачування.

## Докачування

Після введення URL «Потік» перевіряє підтримку докачування запитом діапазону байтів. Стан перевірки з’являється під полем посилання.

Щоб докачати наявний файл, виберіть його папку, введіть точну назву й увімкніть «Докачати наявний файл». Використовуйте частковий файл із того самого посилання, завантажений послідовно від початку, або файл зі збереженим службовим файлом `.aria2`. Для поставленого на паузу завдання зі списку натисніть «Продовжити».

Статус «Очікування з’єднання» з’являється, коли система бачить відсутність мережі й дані не надходять, або коли активне завантаження не просувається чотири секунди. Після аварійного вимкнення незавершені завдання відновлюються під час запуску «Потоку» з останньої записаної на диск точки, якщо сервер підтримує докачування. Сегменти, які не встигли зберегтися, можуть завантажитися повторно.

## Перевірка файлу

У формі додавання розгорніть «Перевірка файлу (необов’язково)». Введіть SHA-256 із 64 шістнадцяткових символів, виберіть файл відокремленого підпису GPG/PGP або задайте обидва. Результат з’явиться в списку завантажень. Якщо перевірка не пройде, файл залишиться на диску й перевірку можна повторити.

Для підпису потрібні GnuPG і відкритий ключ підписанта. У звичайній версії імпортуйте ключ командою `gpg --import public-key.asc`. Для Flatpak імпортуйте його в окреме сховище.

```sh
flatpak run --command=sh io.github.potik.Downloads -c '
    mkdir -p -m 700 "$XDG_DATA_HOME/potik/gnupg"
    gpg --homedir "$XDG_DATA_HOME/potik/gnupg" --import
' < public-key.asc
```

## Налаштування

Відкрийте «Налаштування» кнопкою біля «Додати URL». Задайте типову папку, кількість потоків і ліміт швидкості для нових завантажень. Початкові значення — системна папка завантажень, 8 потоків і відсутність ліміту швидкості. Ці параметри можна змінити для окремого файлу. Налаштування зберігаються у `${XDG_CONFIG_HOME:-$HOME/.config}/potik/settings.json`.

## Встановлення Flatpak

Команда `uname -m` покаже, який пакет вибрати. `x86_64` — 64-бітні Intel та AMD, `aarch64` — 64-бітний ARM. Відкрийте термінал у папці, де збережено файл `.flatpak`.

```sh
flatpak remote-add --user --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo
flatpak install --user "./Potik-$(uname -m).flatpak"
flatpak run io.github.potik.Downloads
```

Для першого встановлення потрібні Flatpak і доступ до Flathub, щоб завантажити середовище GNOME. Пакет містить `aria2c`, запускається під Wayland або X11 і використовує програмне малювання через Cairo. Типова папка завантажень доступна одразу. Для іншої директорії виберіть її у системному діалозі.

Закрийте запущену копію «Потоку» перед переходом на Flatpak. Пакет має окремий профіль налаштувань і черги в `~/.var/app/io.github.potik.Downloads`.

### Збірка пакета

Для створення пакета на комп’ютері цільової архітектури встановіть SDK і розширення Rust. Для підготовки залежностей скрипт використовує `cargo` та `curl`.

```sh
flatpak install --user flathub org.gnome.Sdk//50 org.freedesktop.Sdk.Extension.rust-stable//25.08
./packaging/build-flatpak.sh
```

## Запуск із вихідного коду

Потрібні Rust 1.92+, `pkg-config`, `glib-compile-resources`, GTK 4.10+, libadwaita 1.5+ і `aria2c` у `PATH`. Для збірки встановіть пакети GTK4 і libadwaita з файлами розробки. В Arch Linux встановіть залежності так.

```sh
sudo pacman -S rust pkgconf gtk4 libadwaita aria2
```

Запустіть застосунок із папки проєкту.

```sh
cargo run --locked
```

На дистрибутивах із пакетами Debian назви залежностей для збірки — `pkg-config`, `libgtk-4-dev` і `libadwaita-1-dev`. Пакети мають відповідати зазначеним вище версіям.

## Як це працює

Потік запускає окремий процес `aria2c` і керує ним через JSON-RPC на loopback-інтерфейсі з випадковим токеном. Передавання файлів, розбиття на сегменти й відновлення за файлами `.aria2` виконує сам aria2. У `${XDG_DATA_HOME:-$HOME/.local/share}/potik` зберігаються сесія aria2 та історія завантажень.

Перша версія призначена для прямих посилань, які ви додаєте вручну. Прибирання запису зі списку залишає файл на диску.
